# Model Card Template

Every model card produced by ModelOps must follow this structure.
This mirrors `ModelCardOutputSchema` in `src/lib/modelops/schema.ts` —
if the schema changes, update this template to match.

## Submitted by the user (evidence-based fields)
- **Model Name** — e.g., customer-churn-classifier
- **Version** — e.g., 1.1.0
- **Dataset** — name/identifier of the dataset used
- **Experiment Info** — free-text context on the experiment (defaults to "No experiment details recorded" if not provided)
- **Input Shape** — e.g., "(batch, 128)" (defaults to "Not specified")
- **Data Types** — e.g., ["float32", "int64"] (defaults to empty list)
- **Distribution Summary** — notes on data distribution (defaults to "Distribution data not provided")
- **Metrics** — key-value pairs of measured performance; never estimate a metric that wasn't actually measured
- **Intended Use** — what this model is meant to be used for (defaults to "General evaluation")
- **Warnings** — short flags about sensitive data, edge cases, etc. (defaults to empty list)
- **Limitations** — known boundaries of where the model works reliably (defaults to empty list)
- **Risks** — foreseeable negative consequences of using this model (defaults to empty list)
- **Tests** — test types performed before submission (defaults to empty list)
- **Reproducibility** — seed, script version, run ID; avoid generic phrases like "Standard execution pipeline" — these do not count as real reproducibility detail and earn zero points

## Calculated automatically (never manually entered)
- **Readiness Score** — from readiness_score_detail(), 0–100
- **AI Analysis** — narrative summary generated by the AI layer, always evidence-based
- **Detected Issues** — problems the AI or validators found in the submission
- **Error Reasons** — why a submission failed validation, if applicable
- **Suggested Fixes** — actionable next steps to raise the readiness score
- **Next Steps** — what should happen before this model can be reconsidered
- **References** — sources used, must all appear in docs/source-register.md
- **Evidence** — the specific submitted facts that justify each claim in the card

## Decision
- Always one of: Ready / Ready with reservations / Not ready
- Defaults to "pending_human_review" until a human confirms it
- **Never auto-approved** — a high score is a recommendation, not a final decision

---
**Rule:** Every field must come from evidence the user actually submitted, or be
explicitly marked as a default/gap. Nothing here should ever be invented.
